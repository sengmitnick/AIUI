# 低干扰空间 HUD

`低干扰空间 HUD` 是 AIUI 面向单绿色透明显示眼镜的页面布局规范。它建立在 [Monochrome](/AIUI/design/visual-monochrome) 的色彩、排版和组件 token 之上，补充回答三个问题：**界面该出现在哪里、什么时候出现、以及该占用多少注意力。**

它不是新主题，也不是一套独立 Skill。它是 `monochrome-green` 的空间布局 profile，适用于会展示常驻或瞬时 HUD 信息的全屏 Page。

## 先把眼镜当作一扇窗

眼镜不是手机屏幕。`480 × 352` 是单绿显示的坐标与安全边界，不是一块必须填满的应用画布。真实世界始终是用户正在看的主场景；HUD 只在任务需要时，提供最少、最靠边、最短暂的发光信息。

因此，默认做法不是“做一个全屏页面”，而是：

- 没有待处理信息时不显示 HUD；
- 常驻提示、短操作和状态优先放在下方；
- 中部只留给真正需要注视的任务内容；
- 全屏只可以是游戏、相机、媒体、空间可视化等**内容本身**，不能是通用应用外壳；
- 任务完成后，HUD 应消失或降级为更安静的状态。

## 适用范围

适用：全屏 Page 中的词条提示、播放状态、配对码、短确认、菜单选择、导航线索、游戏状态和空间内容。

不自动适用：对话流卡片、文档阅读器、可复用 Widget、或本身需要高密度信息编排的组件。它们只有在某个明确状态选择了空间 HUD 模式时才使用本规范。

## 先选模式，再选组件

每个稳定的页面状态只能先选一个布局模式。模式变化必须由任务变化驱动，而不是为了把所有信息同时摆上去。

| 模式 | 适用任务 | 默认位置 | 禁止用法 |
| --- | --- | --- | --- |
| `quiet` | 无待办信息 | 不显示 HUD | 用常驻装饰填满画面 |
| `bottom-primary` | 常驻提示、短操作 | 下方主栏 + 页脚 | 用中部大卡片承载通用 chrome |
| `lower-center-moment` | 配对码、一次确认 | 下半部居中 | 常驻整页边框 |
| `top-transient` | 非关键短状态 | 顶部安全条 | 遮挡中心任务内容 |
| `center-task` | 阅读、对象、角色 | 有边界的中央内容 | 放通用状态栏或菜单墙 |
| `immersive-content` | 游戏、相机、媒体 | 全画布任务内容 | 把全屏当应用外壳 |

### 默认模式：`bottom-primary`

下方是常驻 HUD 的默认位置。它把用户主要的物理视野和中央注意力留给现实环境及任务内容，并让状态、提示和操作形成稳定的低位锚点。

在 `480 × 352` 参考画布上，以下数值是来自产品迭代的**起始锚点**，不是对所有佩戴者的生理结论。必须在真机、不同背景和真实任务中验证后再微调：

| Token | 起始值 | 用途 |
| --- | --- | --- |
| `hud-gutter-x` | `28px` | 下方主栏和页脚的左右留白 |
| `lower-rail-bottom` | `58px` | 下方主栏距底部的锚点 |
| `lower-rail-preferred-max-height` | `100px` | 常规状态下主栏的建议最大高度 |
| `footer-bottom` | `14px` | 页脚距底部的锚点 |
| `footer-height` | `18px` | 页脚的紧凑高度 |
| `safe-inset` | 横向 `16px`、纵向 `12px` | 所有必要信息的最小安全区 |

当内容塞不下时，先减少项目、将流程分成状态或升级为有明确阅读任务的 `center-task`。不要为了容纳内容而长出一个通用的整页卡片。

## 一次只制造一个注意力峰值

单绿透明显示的层级不靠第二种颜色，而靠亮度、文字、线条和空白。比 token 更重要的是总量：一个稳定状态里，用户应能立刻知道哪一件事最值得看。

| 元素 | 常规上限 | 规则 |
| --- | --- | --- |
| 最亮文字或数字 | 1 个 | 留给当前必须注意的值、提示或操作 |
| 强描边 | 1 个 | 只标识当前焦点、活动目标或受限任务内容 |
| 局部填充 | 0–1 个 | 仅用于局部选中，最大 `primary-12` |
| 常驻文字组 | 1 个下方主栏 + 1 个页脚 | 其余信息合并、顺序展示或按需出现 |
| 装饰线 | 最少 | 不能帮助定位、分隔或表达进度时就删掉 |

不要把每一个按钮、选项、设置都画成同样亮的圆角框。强描边、箭头和局部填充属于**当前焦点**，而不是菜单墙的默认皮肤。焦点切换时，列表的占位不应跳动。

## 正确与错误的取舍

| 场景 | 推荐 | 不推荐 |
| --- | --- | --- |
| 发音 / 播放 | 当前词条与一个操作放入下方主栏；时间或手势提示放入小页脚 | 顶部同时放资料库、同步、页码，中央再放大卡片 |
| 配对 | 将码作为下半部居中的唯一亮点；倒计时退化成细线或弱文案 | 用整页登录卡、厚边框和多个并列按钮包住一次性信息 |
| 菜单 / 设置 | 仅被选中的一项有强框或箭头；其余选项开放且安静 | 横向排列一串同样亮的方框，让所有设置同时争抢注意力 |
| 角色 / 宠物 | 角色可以居中，因为它是任务内容；状态与操作仍在下方 | 给角色叠加扫描环、雷达、仪表和外壳，把内容做成仪表盘 |
| 游戏 / 相机 | 画面可以占满，因为画面就是内容；得分、音量、返回等 chrome 在边缘或下方 | 借全屏内容之名重新加回手机式顶栏、状态栏和整页面板 |

## AIUI 实现边界

此规范并不要求引入新的运行时能力。对于符合条件的 Page：

1. 先加载 `monochrome-green` 的基础 token；
2. 再加载本 profile 的位置与注意力规则；
3. 用透明的 `<view>` 分组承载下方主栏和页脚；只有导航语义成立时才使用 `<card>`；
4. 以支持的 WXSS `position: relative` / `absolute` 表达锚点；
5. 状态变化可以使用 `transition`，但不要把 CSS `animation`、keyframes 或环境动效当作空间 HUD 的手段；
6. 成功、超时或完成后以数据状态把覆盖层移除或降级，而不是让它一直亮着。

示意：

```wxss
.page {
  position: relative;
  width: 480px;
  height: 352px;
}

.lower-rail {
  position: absolute;
  left: 28px;
  right: 28px;
  bottom: 58px;
}

.hud-footer {
  position: absolute;
  left: 28px;
  right: 28px;
  bottom: 14px;
  height: 18px;
}
```

这只是清晰表达锚点的推荐模式。不要把它误用为普通 Widget 的固定尺寸规则，也不要以 `100vh` 加垂直居中的手机网页方式替代它。

## 设计验收

在黑暗、明亮和视觉杂乱的真实背景上检查每一个稳定状态；再分别在静止、行走和转头时检查。

- 是否在无待办任务时保持 `quiet`？
- 用户是否能一眼说出唯一的当前重点？
- 顶部、中央或全画布是否有明确任务理由？没有就下移或移除。
- 是否存在大面积绿色填充、整页边框或两个以上强描边？存在就降级。
- 焦点是否唯一，且切换时不导致布局跳动？
- 关键文字、数字和图标是否在安全区内，并且不只靠绿色来表达语义？
- 确认、超时或完成之后，界面是否会消失或变安静？

浏览器里的黑色背景只是透明显示的近似预览；不能替代真机可读性和舒适度验证。
